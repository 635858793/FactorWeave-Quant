# 数据库迁移问题修复说明

## 问题描述

迁移数据库后，系统启动时出现以下错误：

```
ERROR | 从数据库加载预警设置失败: no such table: trend_alert_config
ERROR | 从数据库加载高级选项设置失败: no such table: trend_alert_config
```

## 根本原因

`trend_tab.py` 错误地使用了 `enhanced_async_tasks.sqlite` 数据库来存储趋势预警配置。

### 错误分析

**错误代码**（trend_tab.py:100）:
```python
# ❌ 错误：使用了异步任务管理器的数据库
self.db_path = "data/enhanced_async_tasks.sqlite"
```

**问题**:
- `enhanced_async_tasks.sqlite` 是异步任务管理器的专用数据库
- 只包含 `async_tasks` 和 `task_execution_history` 表
- 不包含 `trend_alert_config` 表
- 趋势预警配置应该存储在系统配置数据库中

### 数据库职责划分

| 数据库 | 用途 | 包含表 |
|-------|------|---------|
| **enhanced_async_tasks.sqlite** | 异步任务管理 | async_tasks, task_execution_history |
| **factorweave_system.sqlite** | 系统配置 | config, trend_alert_config, alert_rules, ... |
| **alert_config.sqlite** | 告警配置 | alert_rules, alert_history, ... |
| **metrics.sqlite** | 指标数据 | metrics, performance_stats, ... |

## 解决方案

### 修复内容

**文件**: [gui/widgets/analysis_tabs/trend_tab.py:100](file:///d:/DevelopTool/FreeCode/HIkyuu-UI/hikyuu-ui/gui/widgets/analysis_tabs/trend_tab.py#L100)

```python
# ❌ 修改前
```
